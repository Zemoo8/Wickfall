# Bug log

Real bugs found while building and testing, with cause, fix and the proof that it is fixed.

| # | Date | Found by | Symptom | Cause | Fix | Proof | Status |
|---|---|---|---|---|---|---|---|
| 1 | 2026-10-17 | Headless run | `Tools/unity.ps1` never returned although Unity had exited. | `Start-Process -Wait` also waits for helper processes Unity leaves running (licensing client). | Wait on the Unity process only (`WaitForExit`). | Every later headless run returns. | Fixed |
| 2 | 2026-10-17 | Setup | TMP text could not render (no TMP shaders/settings). | `AssetDatabase.ImportPackage` is deferred in batch mode and never runs before `-quit`. | `Tools/import_unitypackage.py` extracts TMP Essential Resources with their GUIDs. | Font asset built; texts render. | Fixed |
| 3 | 2026-10-17 | Capture | Edit-mode screenshots showed no point lights (only the global light). | `Light2D` builds its mesh and bounds in `LateUpdate`, which never runs for edit-mode objects in batch mode. | `WickfallCapture.PrepareLights` builds them before rendering. | `Docs/Screenshots/lightlab_start.png` shows the player's light. | Fixed (capture tool only; the game was never affected) |
| 4 | 2026-10-17 | PlayMode tests | Interactors, hazard hitboxes and hurtboxes found nothing (brazier unusable, geysers harmless). | Unity 6.2: with `Physics2D.queriesHitTriggers = false`, triggers are excluded even from queries whose `ContactFilter2D.useTriggers` is true. Proven by `PhysicsDiagnostics`. | Project setting on; every query keeps explicit layer masks. | `PhysicsDiagnostics.TriggerQueries_SeeInteractables`, `PlayerTests.Brazier_*`, `PlayerTests.Geyser_*` pass. | Fixed |
| 5 | 2026-10-17 | PlayMode tests | In the Light Lab the flame wheel only had Amber. | Script order: when Core loads, `SceneProfile.Start` can run before `GameSession.Start`, which re-applied the save's loadout over the lab's. | `ApplyProgress` itself respects sandbox mode, whatever the order. | `PlayerTests.FlameSwitch_Costs8Wax_AndFlares` passes. | Fixed |
| 6 | 2026-10-17 | PlayMode tests | Error on loading Core: "Unsupported enum type Feature". | Unity cannot serialize a 64-bit enum field (`PresentationGate.feature`). | Stored as a raw `long` with a typed property. | No error in later runs. | Fixed |
| 7 | 2026-10-18 | R2 bot | The bot walked into an inscription stone, then into the Great Bell's posts, until its step timed out. | Navigation only knew walls; props with solid bodies (inscriptions, braziers, shrines, bell posts) sat in "walkable" cells. | `NavGrid.BlockSolidProps` scans each room group when it loads and blocks cells holding a solid Wall-layer collider (gates excluded: they manage their cells). | `Region2Tests.Nav_BlocksTheCellsOfSolidProps_LikeTheBellPosts`; R1 and R2 bots clear their regions. | Fixed |
| 8 | 2026-10-18 | R1 bot | The R1 bot finished the region without the Blue flame. | An interact press was read only on the frame it arrived and only from a free state; a press at the end of a swing (or the same frame as a buffered attack) was lost — a player would lose it too. | Interact is buffered like attack and dodge (0.15 s); the most recent press wins. | `PlayerTests.Interact_PressedAtTheEndOfASwing_IsBuffered`; `Region1_BotClearsTheRegion` passes. | Fixed |
| 9 | 2026-10-18 | Log review | "The referenced script on this Behaviour (VFX_ExtinguishBurst) is missing" on every pooled prefab. | `PooledObject` (a MonoBehaviour) was declared in `Pooling.cs`; Unity only serializes a MonoBehaviour from a file of the same name, so the saved component pointed at no script (the pool re-added one at runtime). | Moved to `PooledObject.cs`; prefabs regenerated. | `ProjectHealthTests` (no missing scripts in prefabs or build scenes; every MonoBehaviour in its own file). | Fixed |
| 10 | 2026-10-18 | R2 capture | Only one leaf island of the canopy image appeared, small, in the middle of the map. | Unity 6 imported the new large image as "Multiple" and auto-sliced it by transparent islands. | The art importer forces Single for any image without a JSON sheet; the region factory re-imports the canopy image. | `Docs/Screenshots/r2_map.png` shows every canopy patch in place. | Fixed |
| 11 | 2026-10-18 | PlayMode test | Standing at the foot of the east vine, the player was pushed a cell down. | The vine landed in a one-cell notch between two wall faces; the feet circle (r 0.3) was squeezed out. | Every vine gets 3-wide landings at both ends (level script). | `Region2Tests.Vine_RefusesWithoutTheRelic_ThenClimbs`. | Fixed |
| 12 | 2026-10-18 | Code review (R3 level) | In R1 and R2 the first inscription you read showed the region's last text ("the bell opens the way" at the start of R1). | Inscriptions were numbered in map scan order (row by row), not in the order the level script meant. | Level files name each inscription with its number (`Inscription0`…, digits as symbols, `Level.inscription(x, y, n)`); the region factory uses it. | `LevelFileTests.Inscriptions_AreNumbered0ToN_AndTranslated`. | Fixed |
| 13 | 2026-10-18 | R3 PlayMode tests | Conveyors and steam jets never moved the player. | The push expired by frame count, but several frames can pass between two physics steps (about 11 headless; sometimes 2 at 60 fps over 50 Hz physics), so the player's FixedUpdate saw it as stale. | Pushes are kept per physics step (`Time.fixedTime`), for this step and the next. | `Region3Tests.Conveyor_CarriesAStandingPlayer`, `Region3Tests.SteamJet_PushesAlongItsColumn_AndScalds`. | Fixed |
| 14 | 2026-10-18 | R3 bot | After a death the bot replayed its route and stopped at the already-taken White flame shrine. | The bot resumed from its last brazier and repeated one-shot steps. | The bot remembers take/ring steps it has done and skips them. | `Region3_BotClearsTheRegion` (with and without a death). | Fixed (bot only) |
